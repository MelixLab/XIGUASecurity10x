经过深入研究 Sandboxie 源码，我找到了答案：参考引擎使用的是 Sandboxie 内置的 Monitor API（内核驱动级监控），而不是 DLL 注入。

核心发现如下：

Sandboxie 内置 Monitor API
Sandboxie 的内核驱动 SbieDrv.sys 已经通过 minifilter 回调、注册表回调等机制拦截了所有文件、注册表、IPC、管道、网络操作。这些操作被记录在驱动的内部日志缓冲区中，可以通过以下 API 读取：

SbieApi_MonitorControl — 启用/禁用监控
SbieApi_MonitorGetEx — 读取一条 trace 条目（包含类型、路径、PID、TID）
Monitor 类型定义（来自 api_flags.h）

Plain Text

MONITOR_FILE    = 0x0A  // 文件操作
MONITOR_KEY     = 0x0B  // 注册表操作  
MONITOR_IPC     = 0x03  // IPC 通信
MONITOR_PIPE    = 0x02  // 命名管道
MONITOR_NETFW   = 0x0D  // 网络防火墙
MONITOR_SCM     = 0x0E  // 服务控制管理器
MONITOR_DNS     = 0x11  // DNS 查询
MONITOR_RPC     = 0x10  // RPC 调用
每条记录还包含操作结果标志（ALLOWED/DENIED/SUCCESS/FAILURE）。

工作原理
引擎调用 SbieApi_MonitorControl(TRUE) 启用监控
在沙盒中运行恶意软件
Sandboxie 内核驱动自动记录所有资源访问
引擎循环调用 SbieApi_MonitorGetEx() 读取所有 trace 条目
解析条目，映射为行为事件 → 判定 verdict
hsx_timewarp.dll 的真正用途
InjectDll64=hsx_timewarp.dll 不是用于行为收集，而是用于时间欺骗（hook GetSystemTime 等函数，让恶意软件误以为时间已过，从而触发时间相关的 payload）。

当前代码的问题
当前代码使用轮询方式（文件系统快照 diff + 进程树扫描 + 网络连接检查），这会遗漏大量行为。需要改为使用 Sandboxie Monitor API 实时读取内核级 trace 数据。
